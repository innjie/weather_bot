# 히스토리
- 항목별 결정사항에 대한 내용을 정리한다.
- 인프라, 기능 별로 섹션화한다.

## 프로젝트 구조/설계
- (2026-08-14) 언어/프레임워크: Kotlin + JDA로 결정. IntelliJ IDEA 프로젝트 구조와 궁합이 좋고, JVM 기반 안정성 및 코루틴 기반 스케줄링에 유리함.
- (2026-08-14) 날씨/미세먼지 데이터 소스: 기상청+에어코리아(국내 정확도 높음)와 OpenWeatherMap(연동 단순, 해외 지원) 둘 다 지원. `WeatherProvider` 인터페이스로 추상화하고 사용자가 설정 커맨드에서 선택.
- (2026-08-14) 설정 저장소: SQLite + Exposed ORM 사용 예정 (소규모 프로젝트 규모에 적합, 추후 Postgres 등으로 교체 용이).
- (2026-08-14) 스케줄러: OS cron이 아닌 앱 내부 코루틴 기반 스케줄러 사용 (봇 프로세스가 상시 Discord 게이트웨이 연결 유지해야 하므로).

## 인프라
- (2026-08-14) 배포 환경: 저가 VPS/클라우드에서 상시 구동 (Docker + `restart: always`). 알림이 매일 정해진 시각에 발송되어야 하므로 로컬/개인 PC 구동은 배제.

## 개발 환경
- (2026-08-14) IDE: IntelliJ IDEA로 진행 결정. Kotlin 공식 지원(Gradle 동기화, 리팩토링, 코루틴 디버깅)이 VSCode보다 안정적이라 채택.
